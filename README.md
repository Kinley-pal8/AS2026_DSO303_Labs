# DSO303: AWS Practical Labs

**Course:** DSO303
**Student:** Kinley Palden (02230287)

Practical lab submissions for DSO303, built against **[Floci](https://floci.io)**, a local, Docker-based AWS emulator. Each lab builds real infrastructure for a fictional **University Student Management System (USMS)** using the unmodified AWS CLI, so every command, error, and fix is genuine AWS CLI usage rather than a simulation of one.

---

## Repository layout

```
DSO303/
└── aws-floci-course/          # the project: environment + all labs
    ├── docker-compose.yml     # pins the Floci container: image, ports, storage mode
    ├── configs/
    │   ├── course.env         # shared config sourced by every lab (no secrets)
    │   └── lab-0N.env         # ARNs and IDs generated by lab N, consumed by later labs
    ├── policies/              # IAM policy and trust-policy JSON documents (reused across labs)
    ├── labs/
    │   └── lab-0N-topic/
    │       ├── README.md          # working notes for this lab
    │       └── lab-0N-report.md   # graded report with embedded screenshots
    ├── screenshots/
    │   └── labN/               # sN.png = Step N; sN.1.png = same step, additional evidence;
    │                            # sNmyturn.png = the step's "Your turn" exercise
    ├── scripts/
    │   ├── setup/               # floci-up.sh / floci-down.sh
    │   ├── utilities/            # whoami.sh, floci-storage-check.sh, verify scripts
    │   └── cleanup/              # destructive scripts, run only deliberately
    ├── templates/               # aws --generate-cli-skeleton output
    ├── outputs/                  # command output and secrets; gitignored, never committed
    └── notes/                    # personal learning notes and Step "Think about it" answers
```

## Quick start

```bash
cd aws-floci-course
source configs/course.env
./scripts/setup/floci-up.sh
./scripts/utilities/whoami.sh
```

## Daily workflow

```bash
./scripts/setup/floci-up.sh      # start or resume (idempotent)
# ... lab work ...
./scripts/setup/floci-down.sh    # pause; state is kept
```

## Never run these

| Command | Why |
|---|---|
| `docker compose down -v` | `-v` deletes volumes |
| `docker volume prune` | Unfiltered; use `scripts/cleanup/floci-prune-volumes.sh` |
| `floci start ...` | Bypasses Compose; disables persistence |
| `rm -rf ~/floci-data` | That directory is the IAM state |

## Conventions

- All resources are prefixed `usms-`.
- Region: `us-east-1` · Floci account: `000000000000`.
- Storage mode: `hybrid`, bind-mounted to `~/floci-data` (state survives every restart, proven in Lab 01 Step 14).
- Secrets, generated credentials, and raw command output live only in `aws-floci-course/outputs/`, which is git-ignored by two independent `.gitignore` rules and is never committed.
- Screenshots are the evidence trail for each lab report; filenames map directly to the step number they document (see Repository layout above).
